# v0.1 local proof result

This folder records a development-machine smoke run, not a production capacity claim.

## Hypothesis

With three equal fake workers and round-robin routing, 12 requests should complete successfully and divide exactly 4/4/4. Since each worker uses the same fixed delays, their client-observed latency distributions should be broadly similar.

## Reproduce

```bash
INFERLAB_BENCHMARK_OUTPUT=docs/results/v0.1/raw/smoke-local-arm64.json \
  ./scripts/proof-v0.1.sh
```

## Environment

- Date: 2026-07-21
- Host architecture: Apple arm64
- Rust: 1.97.1
- Workload: 12 requests, concurrency 3, three loopback worker processes
- Fake latency: 10 ms initial delay and 10 ms per emitted SSE event

## Interpretation

The raw artifact is generated by the command above. The meaningful v0.1 checks are:

- all requests succeed;
- worker counts are exactly equal;
- TTFT is materially lower than end-to-end latency, demonstrating an incremental client-visible response; and
- `/internal/workers` shows zero in-flight work after streams complete.

Observed in the recorded run:

- 12 successful, 0 failed;
- worker distribution: A=4, B=4, C=4;
- TTFT p50/p95/p99: 27.864 / 31.673 / 31.673 ms;
- end-to-end p50/p95/p99: 156.194 / 162.541 / 162.541 ms; and
- 19.004 requests/second over a 0.631-second wall-clock sample.

Absolute latency and throughput should not be compared with real inference systems. The fake worker mostly sleeps, the processes share one machine, the sample is tiny, and the Python standard-library client is intentionally simple. This run validates the measurement and serving path, not system capacity.
